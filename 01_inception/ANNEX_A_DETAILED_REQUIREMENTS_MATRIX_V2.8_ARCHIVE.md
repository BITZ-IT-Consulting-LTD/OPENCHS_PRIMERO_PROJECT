# Former Annex A — Detailed requirements matrix (archived 9 November 2026)

This is the full former Annex A of the D1 v2.8 inception report, removed from the report to reduce duplication with Annex J. It is retained unchanged for traceability.

## Annex A — Detailed requirements matrix

**Current scope qualification:** apply Section 4 and SCOPE-001–SCOPE-010 to acceptance criteria. Particular outbound operations require contractual confirmation where not explicit in [CT2]; DATA-010 permits only the conditional non-sensitive existence metadata in section 4.4, never initial file transfer.

This wider traceability matrix contains **79 unique IDs**: all 68 Annex J requirements plus 11 pre-existing additional records. Ten existing Annex J IDs absent from the earlier matrix are now included under A.7; no new requirement IDs have been invented. Annex J remains the denominator for section 3.6 and Figure 3.

Original Annex A wording, sources, priorities, statuses and validation references are retained in each record. Current classifications and decisions for shared IDs match Annex J. [RV3] is defined in section 3.1 and does not constitute formal Ministry endorsement. Priorities remain proposals except where supported by the governing contract.

Validation methods: **T** = test; **R** = review / inspection; **D** = demonstration; **E** = evidence of receipt or approval. Existing Annex H scenario references are retained as historical links, not proof of test execution or current scope. Apply the current acceptance criterion: inbound and attachment scenarios are future addendum gates, not initial UAT obligations. Split mixed scenarios before execution, and verify actual deployed response semantics rather than assuming any generic HTTP code proves successful case creation. Annex H itself remains pending separate revision.
